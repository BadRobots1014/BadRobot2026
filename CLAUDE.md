## Commands

```bash
# One-time dev setup
./setup_dev.sh          # Installs pre-commit, ruff, robotpy

# Sync RobotPy dependencies
robotpy sync

# Run tests
robotpy test

# Lint and format (auto-fix)
pre-commit run --all-files
ruff check              # Lint only
ruff format --check     # Format check only

# Deploy to robot
robotpy deploy
```

## Architecture

This is a **FRC (FIRST Robotics Competition) robot** using RobotPy with WPILib's command-based framework.

### Robot Selection

`robot.py` is the entry point. It reads the RoboRIO serial number to select a container:
- Serial `032B4B71` → `KrakenRobotContainer` (primary/competition robot, TalonFX + swerve)
- Serial `032B4B44` → `NeoBotContainer` (practice robot, SparkFlex + swerve)

Both containers wire up subsystems and bind PS4 controller buttons to commands.

### Pattern: Command-Based Robotics

All robot behavior is expressed as `commands2.Command` subclasses. The `CommandScheduler` runs every 20ms. Commands declare `requirements` (subsystems they use), preventing conflicts. The containers bind triggers to commands.

### Hardware Abstraction

`hardware/base/` defines abstract interfaces (`MotorController`, `Encoder`, `LEDController`, `Switch`). `hardware/impl/` provides concrete implementations for TalonFX, SparkMax, SparkFlex, Limelight, etc. This allows subsystems to work with either motor vendor.

### Key Directories

- `subsystems/` — WPILib subsystems (drivetrain, shooter, intake, lights, climber, etc.)
- `commands/` — Individual commands (shoot, intake, climb, face target, etc.)
- `routines/` — Autonomous composite commands (PathPlanner-based sequences)
- `hardware/` — Motor/sensor abstractions
- `generated/` — Auto-generated CTRE Tuner X swerve constants; **do not manually edit**
- `tests/` — pyfrc tests

### Swerve Drivetrain

`subsystems/swerve_drivetrain.py` wraps the CTRE Phoenix 6 `SwerveDrivetrain` class as a WPILib `Subsystem`. Constants (wheel size, PID gains, CAN IDs) live in `generated/tuner_constants.py` (generated by CTRE Tuner X).

### Test Mode

`TEST_MODE_ENABLED` in `robot.py` allows commands to read voltage/velocity targets from NetworkTables instead of hardcoded values, useful for tuning on the bench.

## Code Style

`ruff.toml` enforces strict rules including type annotations (ANN), boolean trap detection (FBT), bandit security checks (S), and isort. The `# noqa` exemptions in ruff.toml cover patterns common in WPILib command overrides where `interrupted: bool` parameters go unused. Python target is 3.13.
